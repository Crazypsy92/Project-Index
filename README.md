# Personal R&D Project Index

A centralized index for my personal development projects, covering project repositories, technical documentation, development progress, testing, and delivery records.

## 1. Overview

This repository serves as the central index for my personal R&D projects. Each independent project is maintained in its own repository.

- **Independent repositories:** Keep source code, dependencies, tests, and documentation organized by project.
- **Centralized navigation:** Find projects by category and access their repositories quickly.
- **Progress tracking:** Record development status, milestones, technical decisions, and pending tasks.
- **Testing and verification:** Preserve test results, failure evidence, and acceptance records.
- **Long-term maintenance:** Track changes, archive completed projects, and retain development history.

## 3. Project Status Definitions

| Status             | Description                                                          |
| ------------------ | -------------------------------------------------------------------- |
| Planned            | Objectives defined; development has not started                      |
| In Progress        | Active development or issue resolution                               |
| Under Verification | Testing, regression, or real-world validation in progress            |
| Maintenance        | Core functionality established; ongoing maintenance and improvements |
| Paused             | Temporarily suspended, with existing results preserved               |
| Completed          | Acceptance criteria for the current scope have been met              |
| Archived           | No longer actively developed; historical records retained            |

Project status should be based on actual evidence. Completing implementation does not necessarily mean that all tests have passed or that the entire project has been accepted.

## 4. Project Documentation Standards

Each project may maintain its own documentation according to its needs. The following information is recommended:

1. **Project Overview:** Objectives, technology stack, responsibilities, and current status.
2. **Technical Design:** Architecture, module boundaries, interfaces, and key decisions.
3. **Development Progress:** Completed work, changes, and outstanding issues.
4. **Testing and Verification:** Test environment, scope, passed and failed tests, and blocked items.
5. **Issue Tracking:** Symptoms, root-cause analysis, troubleshooting, and resolution.
6. **Delivery Records:** Versions, important commits, usage instructions, and deliverables.
7. **Next Steps:** Priorities, prerequisites, and acceptance criteria for upcoming tasks.

For reusable documentation templates, see the [Personal Project Record Templates](https://github.com/Crazypsy92/personal-project-record-templates) repository.

## 5. New Project Registration Workflow

When adding a new project:

1. Create an independent GitHub repository.
2. Add a project README describing its purpose, environment, and usage.
3. Add relevant GitHub Topics.
4. Register the project under the appropriate category in this index.
5. Add the repository link, description, and current status.
6. Update milestones, testing evidence, and next steps as development progresses.

Only the relevant section of this document needs to be updated when a new project is added.

## 6. Repository Management Guidelines

- Use concise, descriptive, lowercase English repository names with hyphens between words.
- Keep each independent project's source code, dependencies, tests, and documentation in its own repository.
- Extract reusable functionality into separate modules when appropriate.
- Use clear Git commit messages and preserve important verification evidence.
- Archive inactive projects when appropriate instead of deleting valuable development history.
- Never commit unauthorized company source code, confidential data, passwords, API keys, access tokens, or other sensitive information to public repositories.
